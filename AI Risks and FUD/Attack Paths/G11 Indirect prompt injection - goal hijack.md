# G11 Indirect prompt injection / goal hijack

Back to [[RQ2 Screening Log]]

Path, lights, and scope call produced with AI assistance under the fixed method in the screening log. Quotes came through automated extraction; verify before citing.

**Harm (as claimed):** Baseline: manipulated outputs, such as scam ads passing AI review or LLM recommendations steered by SEO [\[38\]](../Sources.md#^s38). Maximal: zero-click data exfiltration, credential theft, destructive commands or unauthorized transactions carried out by the victim's own agent [\[38\]](../Sources.md#^s38)[\[76\]](../Sources.md#^s76)[\[41\]](../Sources.md#^s41). NCSC says it "may never be totally mitigated" [\[27\]](../Sources.md#^s27).

**Weakest-link light:** 🟢 (qualified). If the [\[40\]](../Sources.md#^s40) cases turn out not to be indirect injection, it becomes 🟡.

**In scope:** Yes. Step 3 is a failure of system control (instruction integrity). Step 4 is a confidentiality failure (credentials and data) or an integrity failure (unauthorized actions).

**Causal check (H1 falsifier 2):** In every in-the-wild case with enough detail, prompt injection was present but a conventional failure was also necessary, and conventional controls would have broken the chain.
- GTG-50020: the sandbox held production keys for several providers and let them leave ([\[40\]](../Sources.md#^s40): "the actor caused the sandbox to hand over the credentials it held"). Secrets isolation or scoped, short-lived keys with egress limits would have left nothing to take.
- Cline CLI, 17 Feb 2026 (Cline, "Post-mortem: unauthorized Cline CLI npm publish," https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm; Adnan Khan, https://adnanthekhan.com/posts/clinejection/): an issue-triage agent that any GitHub user could trigger had Bash, shared a cache with the release workflow, and a long-lived npm token survived a botched rotation. The injection was the entry point; the harm needed all of those. Running Bash was within the agent's granted permissions, but the triage agent held no publish secret, so the harm needed escalation beyond its grant through the shared cache (an escalation-beyond-grant case, not an intent-gap case) (corrected Nov 5, 2026; see [[RQ4 Rogue AI Incidents]]). Cline does not confirm this was the vector used.
- hackerbot-claw, Feb–Mar 2026 (StepSecurity, https://stepsecurity.io/blog/hackerbot-claw-github-actions-exploitation): the one injection attempt failed; every successful compromise used conventional GitHub Actions flaws.
- LiteLLM deployments ([\[40\]](../Sources.md#^s40): "they used prompt injection to exfiltrate the production API keys used in their cloud-hosted container environments"): too little detail to separate the steps.
- MITRE ATLAS (release 2026.10, https://github.com/mitre-atlas/atlas-data): every prompt-injection case study is tagged Exercise, or is a real attempt that failed or had no established harm: AML.CS0043 (malware with an embedded injection; Check Point found "the prompt injection fails"), AML.CS0072 (AI recommendation poisoning; Microsoft, 10 Feb 2026), AML.CS0074 (UK AISI evaluation agents; "has not identified any resulting real-world harm").

So prompt injection is necessary but not sufficient in the documented cases. No case meets the falsifier.

**Gaps:** In the sources reviewed, [\[40\]](../Sources.md#^s40) does not say whether the GTG-50020 and LiteLLM injections were direct or indirect. This note reads GTG-50020 as indirect because an automated system processed attacker content, but that should be verified against the full report. The last 35k characters of [\[40\]](../Sources.md#^s40) were not read. [\[38\]](../Sources.md#^s38) and [\[39\]](../Sources.md#^s39) record attempts on pages, not successful compromises. Microsoft says no customers were affected by EchoLeak [\[76\]](../Sources.md#^s76).
